# 2C 逐声明裁决矩阵

2C 消费 2A 的 `claims_structured` 与 2B 的 `claim_evidence_packages`。`claim_evidence_audit` 是兼容字段，也是最终报告的声明结果来源；每个输入 `claim_id` 必须出现一次。

## 判定矩阵

| 状态 | 必要条件 | 常见限制 |
| --- | --- | --- |
| 有资料支持 | 同一产品/版本、正文可定位、内容直接相关、关键条件覆盖、没有实质矛盾；功效声明需要研究或检测材料 | 品牌自述不能单独升级为独立功效验证 |
| 部分支持 | 只覆盖子命题或部分条件，或只有品牌自述、背景材料、摘要片段 | 必须列出已覆盖与未覆盖条件 |
| 待核验 | 没有相关材料、只有 UGC、产品身份不明、正文不可得、检索失败或预算耗尽 | 未检索到不等于虚假 |
| 存在冲突 | 同一产品范围内有可定位的明确反证或可比来源发生实质冲突 | 时间不匹配本身不构成反证 |

成分研究不能直接证明成品功效；备案或规格页只能证明其实际记载内容；其他产品或版本的材料不得直接支持当前声明。

## 输出字段

每条结果包含 `claim_id`、`claim`、`original_text`、`status`、`reason`、`source_ids`、`evidence_ids`、`supporting_evidence`、`contradicting_evidence`、`covered_conditions`、`uncovered_conditions`、`limitations` 和 `gaps`。支持与反对依据必须能定位到实际获取的证据片段。

模型只能提交语义候选。服务端会重新检查 ID、证据包关联、产品匹配、内容相关性、正文状态和条件覆盖；未知引用和无法定位的引文会被丢弃。

## 固定样例

- 可信规格页写“50mL”，输入声明为“7天祛斑”：`待核验`，规格事实不能支撑功效。
- 研究正文明确同一产品、同一版本、7 天观察、指标和样本量：`有资料支持`。
- 品牌页写“7天修护”，但没有独立研究：`部分支持`，理由必须保留“品牌自述”。
- 同品牌同系列页面只写“抗皱紧致”，图片声明为“抗皱紧致、养出好气色”，且礼盒版本未确认：可对“抗皱紧致”子命题标为`部分支持`，必须列明礼盒/版本与“好气色”的缺口；不能判为完整支持或冲突。
- 只有用户种草帖或只有 URL：`待核验`。
- 同一产品的可比研究明确显示相反结果：`存在冲突`。
- 只有“28天改善”而没有反驳“7天见效”的材料：不得自动判为冲突。

模型失败、返回畸形 JSON 或遗漏声明时，系统为每条输入声明生成 `待核验` 结果，并在 `gaps` 或 `reason` 中保留失败原因。摘要由已验证结果的状态计数生成，不能重新引入更强的自由文本结论。
